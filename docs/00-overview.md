# Sovalune — Техническое задание. Обзор

> Этот документ — точка входа. Остальные файлы в этой папке детализируют
> отдельные подсистемы. Документ написан так, чтобы его мог использовать
> ИИ-агент (например, Claude Code) как источник истины при реализации —
> без необходимости уточнять архитектурные решения у автора на каждом шаге.

## 1. Что такое Sovalune

Sovalune — платформа для создания и эксплуатации ИИ-агентов с
**долговременной структурированной памятью** и способностью к
**самообучению через верифицированную практику**.

Ключевая идея продукта: маленькая модель (класс 8B параметров) с доступом
к внешней векторной памяти и инструментам может решать задачи, для
которых обычно требуют модели на порядок крупнее — за счёт того, что
знания хранятся не в весах и не заталкиваются целиком в контекст, а
подгружаются точечно, релевантным срезом, в момент необходимости.

Второе ключевое свойство — цикл самообучения: если модель ошибается при
решении задачи, она не просто получает исправление, а проходит полный
цикл верификации (см. `04-self-learning.md`) прежде чем повторно
пытаться решить реальную задачу пользователя.

## 2. Глоссарий

| Термин | Значение |
|---|---|
| **Sovalune Core** | Rust-бэкенд: HTTP/WS API, оркестрация памяти, очереди задач, логирование |
| **Sovalune Storage** | PostgreSQL-совместимое хранилище (Supabase Postgres + расширение `pgvector` + Storage API) — во всех документах называется только "Sovalune Storage", детали провайдера не документируются как часть публичного контракта |
| **Vector Memory** | Подсистема векторной памяти: эмбеддинги, поиск по сходству, консолидация знаний |
| **Model Runtime** | C++/CUDA слой инференса модели (8B) + Python для обучения/дообучения |
| **Self-Learning Loop** | Цикл: ошибка → поиск источников → верификация → тренировка/тест → применение к реальной задаче |
| **Instruction Tool** | Инструмент, который модель может вызвать (function calling) для доступа к Vector Memory, файловой системе, тестам и т.д. |
| **Research Submodule** | Отдельный git-репозиторий (сабмодуль) с исследовательским кодом — экспериментальные пайплайны, ноутбуки, скрипты оценки моделей |
| **Context Weaver** | Компонент в Rust, который решает, какой фрагмент памяти и в каком виде подать модели в контекст, не перегружая его |

## 3. Технологический стек (сводно)

```
Frontend
├── Next.js
├── React
├── Monaco Editor
├── Tailwind CSS
└── Vercel AI SDK

Backend (Sovalune Core)
├── Rust
├── Axum        — HTTP/WS API
├── Tokio       — async runtime
├── SQLx        — типобезопасный доступ к Postgres
└── NATS        — межсервисная шина сообщений / очереди

Model Runtime
├── C++         — инференс-движок (低-level, привязка к CUDA)
├── CUDA        — GPU-вычисления
└── Python      — обучение/дообучение (offline pipeline, не в hot path)

Storage
└── Sovalune Storage — Supabase Postgres + pgvector + Storage API (managed, fork под Sovalune)
```

Полное обоснование выбора и границы ответственности каждого слоя — в
`01-architecture.md`.

## 5. Принципы, которые должны соблюдаться во всех модулях

1. **Модульность прежде всего.** Каждый крупный домен (research, model
   runtime, storage-миграции) — отдельный git-сабмодуль. Локально всё
   собирается в один workspace, но границы модулей не размываются кодом,
   который "быстрее написать в куче".
2. **Rust — единственный владелец состояния.** Все обращения к
   Sovalune Storage и NATS идут только через Sovalune Core. Model
   Runtime и Frontend никогда не обращаются к БД напрямую.
3. **Явные контракты.** Любое взаимодействие между модулями описано в
   `08-api-contracts.md` до того, как пишется код. Агент, реализующий
   один модуль, не должен читать код другого модуля, чтобы понять
   формат данных — контракт должен быть самодостаточным.
4. **Память не заменяет контекст, а обслуживает его.** Context Weaver
   обязан ограничивать объём инжектируемой памяти по токен-бюджету
   (см. `03-vector-memory.md`, раздел "Token Budget").
5. **Самообучение не трогает продовый вес модели напрямую.** Любое
   обновление модели проходит через staged pipeline с верификацией
   (см. `04-self-learning.md`).
