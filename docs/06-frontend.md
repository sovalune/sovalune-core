# Frontend — детальное ТЗ (Next.js)

Репозиторий: `sovalune-frontend`.

## 1. Стек

- Next.js (App Router)
- React
- Tailwind CSS
- Monaco Editor (`@monaco-editor/react`)
- Vercel AI SDK — для стриминга ответов модели и работы с
  chat-подобным UI (`useChat`/`useCompletion` hooks, адаптированные под
  собственный WebSocket/SSE протокол Sovalune Core, см. раздел 3)

## 2. Структура приложения

```
sovalune-frontend/
├── app/
│   ├── (chat)/
│   │   ├── page.tsx                 # основной чат-интерфейс

│   │   └── [memoryId]/page.tsx      # детальный просмотр записи + evidence chain
│   ├── learning-cycles/

│   └── api/

```

## 3. Интеграция с Sovalune Core

- **Next.js API routes не содержат бизнес-логики** — они существуют
  только там, где нужно скрыть секреты (например, если Core требует
  server-to-server ключ) или для SSR data-fetching. Основной трафик
  чата — прямое WebSocket-соединение браузера с Sovalune Core
  (`/ws/chat`).
- Vercel AI SDK используется для UI-примитивов стриминга (плавное
  появление токенов, состояние загрузки, стоп-генерация), но
  транспортный слой адаптирован под протокол Core — не предполагается,
  что Core эмулирует OpenAI-совместимый API (если для скорости
  интеграции на раннем этапе решат сделать OpenAI-совместимый прокси
  в Core — это допустимое architectural decision, но не требование
  этого документа).

## 4. Monaco Editor — сценарии использования

1. Просмотр/редактирование кода, который генерирует модель (например,
   в рамках `PRACTICING`/`TESTING` стадий Self-Learning Loop —
   пользователь может посмотреть, что именно тестировала система).
2. Редактирование raw/consolidated memory записей вручную (для
   ре-курации памяти человеком).
3. Подсветка синтаксиса для JSON Schema Instruction Tools при
   дебаге/конфигурации инструментов.

## 5. Визуализация Self-Learning Loop

Обязательный компонент — раз это ключевая фича продукта, она должна
быть видна пользователю, а не быть "чёрным ящиком":

- Степпер стадий (`DETECTED → ... → COMPLETED/FAILED`) с текущим
  статусом, обновляется в реальном времени через WebSocket подписку на
  события `learning.cycle.stage_changed`.
- Раскрываемая секция evidence — источники, найденные на стадии
  `RESEARCHING`, с confidence score.
- Результаты `TESTING` — pass/fail по синтетическим тестам.

## 6. Дашборд памяти

- Фильтры по `tier` (verified/consolidated/raw), по проекту, по
  временному диапазону.
- Поиск (использует тот же `memory_search`, что и модель — тот же
  эндпоинт, честная демонстрация "что видит модель").
- Возможность вручную промотировать/удалить/пометить запись как
  недостоверную (человек в контуре).

## 7. Состояние и данные

- Серверное состояние (память, циклы обучения, сессии) — через
  data-fetching библиотеку с кэшированием (TanStack Query — выбор
  фиксируется при реализации, но нужен инструмент с явной инвалидацией
  кэша, а не голый `fetch` в `useEffect`).
- Локальное UI-состояние — обычный React state, без избыточных
  глобальных стор-библиотек, если не появится явной необходимости
  (например, сложное состояние Monaco multi-file редактора).

## 8. Дизайн

- Tailwind — единственный источник стилей, без CSS-in-JS дублирования.
- Тёмная тема по умолчанию (типично для dev-инструментов), с
  возможностью светлой.
- Для конкретной визуальной айдентики (цвета, типографика, тон) —
  см. отдельно `frontend-design` guidance при реализации, этот
  документ фиксирует только структуру и функциональность, не
  визуальный стиль.
